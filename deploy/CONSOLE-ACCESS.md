# Защита доступа и история консоли

## Обновление Raspberry Pi

    cd /opt/ServersStatus
    sudo git pull --ff-only origin main
    sudo cp deploy/serversstatus.service /etc/systemd/system/serversstatus.service
    sudo systemctl daemon-reload
    sudo systemctl restart serversstatus

Обновлённая web-служба читает существующий /etc/serversstatus-telegram.env через
systemd EnvironmentFile. В нём уже используются STATUS_TELEGRAM_TOKEN,
STATUS_TELEGRAM_CHAT_ID и, при необходимости, STATUS_TELEGRAM_PROXY (Hysteria).
Токен/ключи не нужно переносить в код или отправлять в чат. Файл должен оставаться
защищённым и доступным systemd; не открывайте его на чтение всем пользователям.

Если systemd unit у вас дополнительно настроен вручную, сохраните эти изменения;
существенная новая строка: EnvironmentFile=-/etc/serversstatus-telegram.env.
Для кодов используется тот же Telegram-чат. Предпочтителен личный чат владельца.
Коды отправляются круглосуточно по запросу входа, независимо от расписания
автоматических предупреждений.

## Один раз установить постоянный PIN

На Pi из /opt/ServersStatus:

    sudo -u serversstatus env STATUS_DB=/var/lib/serversstatus/status.sqlite3 /opt/ServersStatus/.venv/bin/python -m server.console_access

Команда дважды запросит 4 цифры без отображения ввода. Выберите PIN в терминале,
не присылайте его в чат. В базе хранятся соль и scrypt-хеш, не открытый PIN.
Команда также сбрасывает прежние допуски, незавершённые коды и блокировки
дополнительного входа. При смене/утрате PIN выполните ту же команду локально.
Если путь STATUS_DB отличается в вашей установке, используйте свой путь.

Новый PIN применяется сразу после завершения команды.

Для этих изменений агенты обновлять не нужно: обработка допуска и хранения —
на портале. Локальный allow_remote_console по-прежнему нужен для работы команд.

## Как открыть доступ

После обычного входа на портал сверху есть «Снять защиту».

1. Введите постоянный 4-значный PIN.
2. В Telegram придут 6 случайных цифр. Введите их на портале.
3. В Telegram придёт новый код из 6 цифр и знаков. Введите его.

Только после третьего шага появляется доступ к консоли на страницах серверов
и к API её истории/выполнения/ввода. До этого консоль и её метаданные отсутствуют
в HTML страницы, включая исходный отчёт. Каждый код действует 5 минут и связан
с конкретным сеансом и шагом. Повторное применение/другой браузер не подходят.
Два неправильных ввода дают блокировку 15 минут, следующие блокировки ×3.
Отправка кодов дополнительно ограничена шестью за минуту на портал.
Если Telegram недоступен, допуск не выдаётся.

Это две проверки фактора: известный владельцу PIN и доступ к Telegram,
реализованные тремя последовательными шагами. Оба одноразовых кода приходят
в один настроенный Telegram-чат. Коды не пишутся в журналы и хранятся в базе
только как HMAC-хеши с отдельными nonce. После успеха выдаётся отдельная
Secure/HttpOnly/SameSite=Strict cookie, связанная с основной сессией. Нужен HTTPS.
Одна основная cookie без дополнительной доступ не открывает.

Допуск действует 15 минут. Через «Снять защиту» можно открыть страницу состояния
и нажать «Включить защиту» раньше. Выход из основного аккаунта тоже закрывает
доступ. После истечения консоль исчезает при следующем запросе виджета,
API сразу запрещает чтение и управление. Уже запущенная команда может завершиться
по своему прежнему лимиту; включение защиты не откатывает её действия.

## История

По умолчанию видны запросы, созданные за последний час. «Очистить» скрывает
завершённые записи только визуально в текущей вкладке/браузерном сеансе,
не удаляя базу. Выполняющиеся задания остаются доступными для ввода/остановки.
«Показать всю историю» открывает архив за последние 6 календарных месяцев,
независимо от визуальной очистки. Большой архив загружается страницами по 100
записей кнопкой «Показать ещё». Можно вернуться к последнему часу.

Прежний лимит хранения 100 команд на сервер отменён. Записи старше шести
месяцев удаляются при обслуживании базы на входящих отчётах (обычно не реже
раза в час при работающем мониторинге), а также при чтении/создании истории.
Счётчик job ID сохраняется отдельно и не сбрасывается после очистки: это важно
для защиты агента от повторного выполнения. Исходные команды/вывод хранятся
в базе до истечения срока; не используйте визуальную очистку как удаление
секретов. Включение защиты скрывает и архив.

## Проверка после установки

- До проверки PIN/Telegram кнопки и содержимое мини-консоли отсутствуют.
- После PIN и первого Telegram-кода консоли всё ещё нет.
- После второго Telegram-кода консоль доступна; настройки агента сохраняются.
- В истории за час нет старых запросов, но они видны в архиве.
- После «Очистить» архив по-прежнему содержит эти записи.
- После «Включить защиту» прямые запросы к API тоже получают отказ.

Ранее удалённые старым лимитом записи не восстанавливаются: архив сохраняет имеющиеся и все новые команды. Публичные Swagger/OpenAPI-страницы отключены, чтобы не раскрывать закрытые возможности через автодокументацию.
