# Чат с локальной моделью в портале

Связь уже проверена пользователем: на Raspberry Pi
`curl http://127.0.0.1:18091/health` → `{"status":"ok"}`.
Модель работает на Backup/windows-02 через ограниченный обратный SSH-туннель.

## Включить чат

**Ключ не присылать в чат ChatGPT, Telegram, Git или журналы.**
Он передаётся только в локальный защищённый файл на Raspi.

1. Сначала на **Raspberry Pi** обновите портал и запустите настройку:

```bash
cd /opt/ServersStatus
sudo git pull --ff-only origin main
sudo bash /opt/ServersStatus/deploy/ai-ssh/Enable-PortalAI.sh
```

Дождитесь `Paste API key ... (hidden):` и оставьте терминал ожидающим ввода.

2. Теперь на **Backup**, PowerShell от администратора, скопируйте ключ в свой
   буфер обмена (команда не печатает его):

```powershell
Set-Clipboard -Value ([IO.File]::ReadAllText('C:\ProgramData\ServersStatusAI\api-key.txt').Trim())
```

Сразу вернитесь к ожидающему терминалу Raspi, вставьте ключ и нажмите Enter.
Не копируйте другие команды между копированием ключа и его вставкой.

В строке `Paste API key ... (hidden):` вставьте ключ из буфера и нажмите Enter.
Символы не отображаются. Скрипт проверяет health и авторизацию `/v1/models`
(в llama.cpp b12110 этот endpoint требует ключ), затем атомарно сохраняет ключ
в `/var/lib/serversstatus/ai-api-key`, owner `serversstatus`, mode `0600`, и
перезапускает только веб-службу `serversstatus`. При неверном ключе старый файл
не заменяется. Ключ не попадает в аргументы curl и внешний HTTP proxy.

3. Войдите в портал как администратор и откройте **«ИИ-помощник»** вверху или:

```text
https://panel.vikserver.ru/ai
```

После настройки можно очистить локальный буфер Windows:

```powershell
Set-Clipboard -Value ''
```

Модель, Windows-службу и SSH-туннель обновлять не требуется.
Новые зависимости и изменения Caddy не нужны.

## Возможности первого этапа чата

- Постепенный вывод ответа, Enter/Shift+Enter, сохранение черновика.
- Новый диалог, мгновенное переключение истории, отмена ответа и удаление диалога.
- История строго своей учётной записи, до 186 дней; при удалении пользователя
  его AI-история также удаляется, чтобы новый аккаунт с тем же именем её не получил.
- Администратор/суперадмин; роль текущего просмотра не получает доступ к чату.
  Console-unlock не нужен: помощник только формирует текст, команды не исполняет.
- До 50 диалогов и 50 вопросов в каждом, один незавершённый запрос на пользователя,
  до трёх запросов в общей очереди, один активный запрос к модели.
- Контекст — system prompt, текущий вопрос и до четырёх последних полных пар
  текущего диалога, с лимитом 8000 символов. Максимум 4000 символов на вопрос,
  512 новых токенов, 180 секунд обработки, до 16384 символов сохранённого ответа.
- Ответы — безопасный текст, без исполнения HTML, команд или tool calls.

**Интернет-поиск, текущие метрики портала и 1С пока не подключены.** Модель
не имеет доступа к файлам/бэкапам/консоли и не может проверять факты онлайн.
Их добавление — отдельные этапы с ограниченными инструментами, а не shell-доступом.

## Как работает

Портал обращается только к фиксированному `http://127.0.0.1:18091`, передавая
ключ из локального файла. URL/ключ не отправляются браузеру, redirect и внешний
proxy отключены. Отдельный фоновый обработчик читает OpenAI SSE и сохраняет
части ответа; браузер получает их короткими запросами примерно раз в секунду.
Поэтому Caddy с прежними 15/30-секундными таймаутами менять не требуется и
генерация не держит долгие HTTP-запросы браузера.

Повтор отправки с тем же nonce не создаёт двойного запроса. Отмена закрывает
поток модели, завершённые ответы и приватная история не смешиваются между
пользователями. После рестарта незавершённый ответ отмечается как прерванный,
не воспроизводится автоматически. Ключ хранится отдельно от базы и истории.

## Диагностика

- Нет настройки: проверьте существование/права `ai-api-key`, повторите скрипт.
- Нет связи/модель приостановлена: проверьте health, туннель и RAM/паузу Backup.
- Модель отклонила ключ: снова перенесите правильный ключ с Backup.
- Длинный запрос: сократите вопрос/контекст или начните новый диалог.
- Для локального ручного выбора другого key-file администратор может задать
  `STATUS_AI_KEY_FILE` в окружении веб-службы. Браузер этот путь не задаёт.

В тестах используется искусственный SSE-сервер/transport, не реальная модель
пользователя. Финальную скорость и работу через ваш туннель проверим первым
вопросом в портале после переноса ключа.
