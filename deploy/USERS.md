# Пользователи и доступ

## Возможности

| Доступ | Что доступно |
| --- | --- |
| Пользователь | Текущий обзор и текущие сведения о сервере/процессах/службах. История, графики, снимки, настройки и административные страницы закрыты. |
| Администратор | Текущие сведения, история/графики/снимки, журнал и административные настройки, включая управление агентами и обновлениями. Консоль и действия RDP закрыты. |
| Суперадмин | Полный доступ и управление пользователями. Для консоли/RDP дополнительно нужна прежняя трёхэтапная проверка. |

Пользователь `admin` сохраняет основной полный доступ. Удалить или понизить
его через портал нельзя. У остальных пользователей их список, названия ролей,
выбор ролей и журнал операций с учётными записями в интерфейсе/API скрыты.
При попытке открыть скрытые страницы напрямую возвращается обычный 404.
Роли не передаются в cookie или публичный JSON-профиль.

## Где управлять

После входа под `admin` или другой полной учётной записью откройте
«Администрирование» → «Пользователи». Можно:

- создать пользователя с логином до 64 букв латиницы/кириллицы, цифр/`_.-`, паролем
  12–256 символов и выбранным доступом;
- изменить доступ и включить/отключить учётную запись;
- задать новый пароль;
- удалить пользователя с подтверждением его логина.

Операции требуют сеанса и CSRF. Пароли хранятся как scrypt-хеш с новой солью,
не возвращаются в форму и не записываются в журнал. Изменение пароля,
отключение/изменение доступа и удаление отзывают все сеансы пользователя,
включая допуски и коды проверки консоли. Основной доступ и собственную текущую
учётную запись нельзя удалить/отключить/понизить; собственный пароль менять
можно, после этого потребуется войти снова.

## Обновление существующей установки

```bash
cd /opt/ServersStatus
sudo git pull --ff-only origin main
sudo systemctl restart serversstatus
```

При первом открытии базы создаются таблицы ролей и привязки сеансов к
пользователям. Старые сеансы не имели имени владельца, поэтому они отзываются:
потребуется снова войти с существующим паролем. `admin` сохраняет полный доступ;
если его нет, полный доступ получает первая существовавшая учётная запись.
Остальные старые учётные записи получают текущий просмотр, пока владелец не
изменит доступ. Новый `create-admin` через локальную CLI создаёт полный доступ.

Агенты Windows/Linux используют отдельные Bearer-ключи и продолжают отправлять
данные. Обновление агентов и повторная настройка PIN/Telegram не требуются.
Ограничения выполняются на сервере для прямых URL и API, а элементы интерфейса
формируются с учётом доступа текущего сеанса.


## Создание и состояние учётных записей

Логины поддерживают кириллицу (включая Ё/ё), латиницу, цифры и `_.-`, без пробелов,
до 64 символов. Дубликаты с другим регистром не создаются. При неверном логине,
роли, пароле или занятом имени возвращается страница с понятной ошибкой,
сохраняются логин/выбор доступа; пароль никогда не выводится обратно. Регистр
логина при входе, как и раньше, должен соответствовать сохранённому имени.

В карточке есть отдельная кнопка «Отключить учётную запись»/«Включить».
Отключение немедленно завершает сеансы и консольные разрешения, отменяет ожидающие
запросы ИИ. Основной admin и собственный доступ отключить нельзя. Смена роли
через форму не включает отключённую запись, даже если страница была открыта
до отключения другим администратором.

## Временная блокировка после ошибок входа

Наряду с прежней защитой по IP теперь отдельно учитываются ошибки известного
логина: две ошибки — 15 минут, последующие серии увеличивают срок втрое.
Блокировка логина действует и при попытке входа с другого IP. Правильный пароль
не обходит активную блокировку; успешный вход обнуляет ошибки, но не историю
усиления защиты. Неизвестные логины не создают строки счётчиков пользователей.
Это правило нового входа: существующие сеансы временная блокировка не отзывает.
Административное отключение, напротив, отзывает сеансы сразу.

В карточке показывается «Вход заблокирован до дд.мм.гггг чч:мм:сс МСК» и кнопка
снятия блокировки логина. Блокировки IP с датами показаны отдельно ниже списка,
поскольку один IP могут использовать несколько людей. У IP своя кнопка снятия;
разблокировка логина не отменяет ограничение IP, а снятие IP не включает
отключённого пользователя. Ручное снятие обнуляет ошибки/срок, сохраняя множитель.
Счётчики логина начинаются после этого обновления: прежние блокировки известны
только по IP и не приписываются задним числом конкретному человеку.

Новые действия доступны только admin/суперадмину, требуют CSRF, пишутся в закрытый
журнал пользователей. Миграция создаёт account_auth_guard автоматически,
пользователи/пароли/роли сохраняются. Для установки достаточно git pull и
перезапуска serversstatus. Новых зависимостей или обновления агентов нет.
