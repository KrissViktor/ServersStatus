# Мини-консоль сервера

На подробной странице сервера доступна неинтерактивная консоль: PowerShell 5.1
для Windows и /bin/bash для Linux. Команда идёт через существующий HTTPS-канал
агента; открывать RDP/SSH или дополнительные порты не нужно.

## Установка

На Raspberry Pi обновите панель:

    cd /opt/ServersStatus
    sudo git pull --ff-only origin main
    sudo systemctl restart serversstatus

Дождитесь успешных сборок Windows/Linux. Через «Обновления → Проверить GitHub»
обновите агенты. Консоль выключена по умолчанию и требует отдельного локального
разрешения. Настройки мониторинга через панель не могут включить это разрешение.

### Windows: включить один раз

В PowerShell от администратора:

    $path = 'C:\ProgramData\ServersStatus\config.json'
    Copy-Item $path "$path.before-console" -Force
    $config = Get-Content $path -Raw -Encoding UTF8 | ConvertFrom-Json
    $config | Add-Member -NotePropertyName allow_remote_console -NotePropertyValue $true -Force
    [IO.File]::WriteAllText($path, ($config | ConvertTo-Json -Depth 30), (New-Object Text.UTF8Encoding($false)))
    Restart-Service ServersStatusAgent

В Windows-артефакте GitHub Actions также есть Enable-RemoteConsole.ps1:

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Enable-RemoteConsole.ps1

Для отключения — -Disable либо allow_remote_console=false и перезапуск службы.
Остальные настройки, включая ключ и правила бэкапов, сохраняются.

### Linux: включить один раз

От root отредактируйте /var/lib/serversstatus-agent/config.json, добавив поле
"allow_remote_console": true. Сохраните корректный JSON и текущие права файла
(root:serversstatus-agent 640). Затем:

    systemctl restart serversstatus-agent

Python агенту уже установлен; дополнительных пакетов не требуется. Для отключения
установите false и перезапустите службу. Локальный монитор самой Raspberry Pi
консоль не предоставляет.

## Права и поведение

Windows-команда выполняется с правами учётной записи службы — LocalSystem при
стандартной установке. Linux-команда выполняется как serversstatus-agent с
ограничениями systemd (NoNewPrivileges, ProtectSystem и др.). Консоль не повышает
права и не меняет ограничения Linux-службы: запись обычно доступна только в её
каталог состояния, sudo не предусмотрен. Учётная запись и оболочка видны в панели.

Команды могут изменять сервер с этими правами. Перед запуском отметьте целевой
сервер. Например:

    Get-Service | Select-Object -First 10
    Get-Process | Sort-Object WorkingSet -Descending | Select-Object -First 10

Linux:

    uptime; df -h /
    systemctl status nginx --no-pager

Каждый запуск — новая оболочка с рабочим каталогом конфигурации агента.
Переменные и cd между командами не сохраняются. Нет интерактивного ввода, полноценного терминала, editor/top или запросов пароля. Для составной команды используйте один блок/строку. На обновлённых агентах вывод появляется по мере выполнения, итоговый код — после завершения. Стандартный вывод и ошибки объединены, отображаются код выхода
и таймаут. Вывод PowerShell настраивается на UTF-8; внешние Windows-программы могут
использовать собственную OEM-кодировку.

Ограничения: команда до 4000 символов, 15/30/60 секунд в интерфейсе (API 1–60),
вывод до 16 Кб. Временной лимит завершает процесс и обычных дочерних процессов:
на Windows используется Job Object, на Linux отдельная группа процессов.
Фоновые задачи через консоль не поддерживаются; изменения в системных службах
и других внешних ресурсах, сделанные командой, после её завершения сохраняются.
Процесс не получает интерактивный stdin.

## Очередь, журнал и восстановление

Одна команда за раз на сервер. Консоль, обновление программы агента и команды
управления Windows взаимно блокируются. Отправка требует действующей сессии,
CSRF, подтверждения сервера, свежего отчёта до 60 секунд и локального разрешения.
Команда в очереди истекает через 90 секунд. Агент сохраняет её ID до исполнения
и получает разрешение на приём; повторно тот же или более старый ID не запускает.

При сбое агента или потере подтверждённого результата состояние может стать
неизвестным. Дождитесь связи и проверьте сервер локально; только затем используйте
кнопку подтверждения локальной проверки. Она разрешает следующие команды и не
отменяет эффекты предыдущей. Если вернуть из резервной копии базу с меньшими ID,
сначала проверьте серверы: агент намеренно отвергает старые ID во избежание повтора.

В карточке показываются последние 20 запусков, база хранит последние 100 на сервер.
Команды и результаты сохраняются в базе портала; не вводите в них пароли и ключи.
Общий журнал событий фиксирует назначение и результат с ID без дублирования текста
команды/вывода. История доступна после входа в панель; агент видит только своё задание.
Команды и результаты отображаются как текст, без выполнения HTML/JavaScript.
Сортировка процессов, ввод команды и раскрытые записи не сбрасываются при обновлении.


## Живой вывод

После обновления панели и агента промежуточный stdout/stderr передаётся во время
работы команды. Панель опрашивает результат примерно раз в секунду при активном
задании и реже в ожидании. Запуск, как и раньше, начинается после получения
задания агентом на его очередном цикле. Старые агенты продолжают присылать итог
после завершения; панель предлагает обновить их для потокового вывода.

Передача прогресса идёт в отдельном потоке с коротким сетевым таймаутом:
недоступность панели не продлевает лимит исполнения команды. Отправляется полный
ограниченный снимок вывода, очередь хранит только последнее состояние. Поздний
прогресс не может перезаписать завершённый результат. Промежуточные отчёты не
засоряют общий журнал событий. Если результат неизвестен после сбоя, уже
полученный частичный вывод сохраняется.

Вывод автоматически прокручивается к концу, если пользователь находился внизу;
при чтении более ранних строк сохраняется положение. Текст следующей команды
не сбрасывается. Некоторые программы буферизуют вывод при работе без терминала;
для Python можно использовать -u. Лимиты 60 секунд/16 Кб сохраняются.

Живой вывод не является полноценным TTY: ответить запущенной команде, вводить
пароли или управлять editor/top пока нельзя. Отдельный пароль на доступ к
консоли пользователем предложен на будущее и в этой версии не включён:
действуют существующие вход, CSRF, локальное разрешение и подтверждение сервера.
