# Кнопки Telegram и наблюдение за ботом

Используются существующие токен, ID чата и STATUS_TELEGRAM_PROXY из файла
/etc/serversstatus-telegram.env. Windows/Linux-агенты обновлять не требуется.

## Установка на Raspberry Pi

    cd /opt/ServersStatus
    sudo git pull --ff-only origin main
    sudo systemctl restart serversstatus

    sudo cp deploy/serversstatus-bot.service /etc/systemd/system/
    sudo systemctl daemon-reload
    sudo systemctl enable --now serversstatus-bot
    systemctl status serversstatus-bot --no-pager

В чате с вашим ботом отправьте /start. Появится постоянная клавиатура:

- Статус — доступность, CPU/ГГц, RAM/объём и диски всех серверов.
- Отчет — сводка за последние 24 часа и текущее состояние, сразу по запросу.
- RDP — пользователи, домены, ID и состояния RDP-сессий по Windows-серверам.
- Предупреждения — текущие проблемы панели, включая ранние дисковые от 85%.
- Панель — ссылка на портал.
- Помощь — описание кнопок.

Альтернативы: /status, /report, /rdp, /warnings, /panel, /help.
Написание «Отчёт» тоже распознаётся. Неизвестные обычные сообщения игнорируются.

Ответы по кнопкам доступны круглосуточно. Они не помечают плановую суточную сводку
отправленной. Автоуведомления сохраняют прежнее расписание (будни 08–20, выходные
12–20 МСК) и порог дисков 98%. «Предупреждения» — явный ручной запрос всех ранних
проблем; это не включение автоматического спама от 85%.

## Доступ

Команды обрабатываются только из STATUS_TELEGRAM_CHAT_ID. Другие чаты не получают
ни отчётов, ни подсказок. В групповом чате это разрешает команды всем его участникам.
Чтобы ограничить конкретных участников, добавьте в защищённый env-файл:

    STATUS_TELEGRAM_ALLOWED_USERS=123456789,987654321

Это Telegram user IDs, не имена. Для другого адреса панели:

    STATUS_PANEL_URL=https://panel.vikserver.ru

После изменения env-файла перезапустите постоянную службу:

    sudo systemctl restart serversstatus-bot

В группе privacy mode Telegram может скрывать обычный текст кнопок: используйте
команды вида /status@ИмяВашегоБота. Для личного чата достаточно /start.

Бот только читает данные. Он не перезапускает серверы/службы, не меняет настройки
и не раскрывает ключи агентов. Есть ограничитель команд и длины очереди.
Старые команды старше 10 минут не выполняются; просроченные ожидающие ответы
не рассылаются после долгого отсутствия сети.

## Наблюдение Raspberry Pi

Отдельная служба включена в автозапуск, Restart=always. При падении перезапускается
через 10 секунд. WatchdogSec=120 требует регулярный heartbeat от самого процесса;
при зависании systemd завершает его и запускает заново. Временные ошибки Telegram
повторяются с паузой, включая retry_after. Состояние процесса обновляется и при
ожидании восстановления сети. Общая SQLite хранит курсор getUpdates и прогресс
ответов, поэтому обычный перезапуск не повторяет уже обработанные команды.
После SIGTERM процесс штатно завершает работу.

В веб-панели откройте ссылку «Бот»: показаны последнее состояние процесса,
успешный опрос Telegram, доставка ответа и число ожидающих ответов.
Страница доступна только после входа; токен там не отображается.

Диагностика:

    journalctl -u serversstatus-bot -n 40 --no-pager

Если видите код 409, обычно бот уже получает getUpdates в другом процессе либо
включён webhook. Для этого проекта нужен один получатель команд, без webhook.
Не запускайте --discover-chat одновременно с постоянным ботом: для повторного
поиска ID сначала остановите serversstatus-bot и затем запустите обратно.
Старый таймер serversstatus-notify продолжает отправлять автоматические тревоги
и суточные сводки; он не читает getUpdates и не конфликтует с получателем команд.

Служба бота использует существующий SOCKS/Hysteria2-прокси только для Bot API.
При перезапуске не отправляется приветствие — клавиатура приходит в ответ на
/start или команду. Сетевые ошибки логируются без токена.

При потере ответа Telegram после принятия сообщения возможен дубль: Bot API
не обеспечивает строго однократную отправку. Если выключится сам Raspberry Pi,
он не сможет сообщить о своём отключении — для этого нужен внешний мониторинг.

## Обновление в будущем

    cd /opt/ServersStatus
    sudo git pull --ff-only origin main
    sudo systemctl restart serversstatus serversstatus-bot

Если менялся unit-файл, скопируйте новую версию и выполните daemon-reload перед
restart. Не копируйте пример env-файла поверх рабочего токена.

## Кнопка «Бэкап»

Показывает по каждому серверу с настроенными проверками название правила,
папку, имя файла, размер, свежесть, дату копии и точный возраст:
например 31 ч 2 мин 7 с. Можно вызвать командой /backup.
Дни переводятся в суммарные часы, секунды не скрываются.

Для SQL правил с date_from_filename используется дата из имени .bak.
Для обычных файлов — метка изменения, а не выдуманная дата создания.
Старый формат агента поддерживается: дата показывается во времени агента,
возраст увеличивается с момента последнего отчёта. Новый агент дополнительно
передаёт timestamp даты копии, который отображается в МСК.
Если сервер недоступен, свежесть явно не подтверждается; будущая дата — ошибка.

В Telegram-отчётах рабочие/онлайн состояния отмечены 🟢, отключения и ошибки — 🔴.
Отсутствие настройки/данных — ⚪, проверка стабильности — 🟡.
После обновления и перезапуска службы отправьте /start: клавиатура обновится.
