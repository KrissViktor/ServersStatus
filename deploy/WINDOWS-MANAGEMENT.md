# Windows Update и перезагрузка из панели

Поддерживаются Windows Server 2019 и Windows 10 со штатным агентом LocalSystem.
Linux и сама Raspberry Pi этими командами не управляются.

## Обновить панель и агенты

На Raspberry Pi:

    cd /opt/ServersStatus
    sudo git pull --ff-only origin main
    sudo systemctl restart serversstatus

Дождитесь успешной новой сборки GitHub Actions. Через «Обновления → Проверить
GitHub» назначьте новую версию Windows-агентам. У агентов без первоначальной
поддержки обновления потребуется прежний ручной шаг, см. UPDATES.md.

Данные Windows Update появятся на подробной странице сервера. По ссылке
«Управление обновлениями и перезагрузкой Windows» открываются команды и их история.

## Один раз разрешить управление на каждом Windows-сервере

По умолчанию доступны только сведения, управление выключено. Включение выполняется
локально администратором, чтобы доступ к панели сам по себе не включал управление ОС.

В PowerShell от администратора (ключ не выводится, остальные поля сохраняются):

    $path = "$env:ProgramData\ServersStatus\config.json"
    Copy-Item $path "$path.before-management" -Force
    $config = Get-Content $path -Raw -Encoding UTF8 | ConvertFrom-Json
    $config | Add-Member -NotePropertyName allow_windows_management -NotePropertyValue $true -Force
    [System.IO.File]::WriteAllText($path, ($config | ConvertTo-Json -Depth 30), (New-Object System.Text.UTF8Encoding($false)))
    Restart-Service ServersStatusAgent

В артефакте ServersStatus-Windows-x64 также есть Enable-WindowsManagement.ps1,
который выполняет тот же шаг. Из распакованного каталога:

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Enable-WindowsManagement.ps1

Для отключения: тот же скрипт с -Disable либо значение $false вместо $true
в примере выше. После изменения нужен перезапуск агента. Отключение запрещает
новые команды; начатая установка Windows Update может продолжаться в самой ОС.

## Возможности

- Последние 10 записей установок Windows Update и их результат, последние
  10 исправлений Get-HotFix с KB/датой. История обновляется в фоне каждые 15 минут,
  поэтому основной сбор метрик не ждёт PowerShell.
- Признаки необходимости перезагрузки: Component Based Servicing, Windows Update
  и ожидающие операции с файлами. Проверяются при каждом отчёте; при нехватке прав
  показывается неизвестный статус, а не ложное «перезагрузка не нужна».
- «Проверить доступные обновления»: поиск через Windows Update Agent с текущими
  настройками источника (включая WSUS). Результат — количество и первые 20 названий.
- «Установить обновления»: повторный поиск подходящих обновлений, загрузка и установка.
  Устанавливаются доступные не скрытые программные обновления; драйверы,
  обновления версии ОС (категория Upgrades), необязательные обновления BrowseOnly
  и требующие интерактивного ввода исключены.
  Агент может принять EULA найденных обновлений. Выбор отдельных KB в этой версии
  не предусмотрен. Проверка и установка — разные команды; состав обновлений
  между ними может измениться.
- «Перезагрузить через 5 минут»: штатный shutdown.exe с задержкой 300 секунд
  и предупреждением Windows. Для подтверждения нужно ввести ID сервера.
  **Windows при задержке может принудительно закрыть приложения и потерять
  несохранённые данные.** Заранее предупредите RDP-пользователей и сохраните работу.
- «Отменить перезагрузку»: shutdown /a. Он отменяет действующий системный таймер,
  в том числе назначенный вне панели. Если таймера нет или отменять уже поздно,
  команда завершится ошибкой.

Установка не запускает перезагрузку сама. Самостоятельная политика Windows/GPO
продолжает действовать. Для установки также нужно ввести ID сервера.
Обслуживание может занимать много времени и повышать CPU/диск, поэтому выбирайте
подходящее время с учётом 1C/SQL и пользователей. Существующий график Telegram
не ограничивает выполнение команд администратора.

## Выполнение и проверка результата

Команда требует входа, CSRF, свежего отчёта (до 60 секунд), поддержки агентом и
локального разрешения. В очереди она живёт 90 секунд: давно отключённый сервер
не выполнит старую перезагрузку при возвращении в сеть. Перед выполнением агент
сохраняет ID на диск и получает подтверждение приёма от панели. Повторно тот же
ID не выполняется. Отмена команды по потере HTTP-ответа не подразумевается.

Одна команда выполняется за раз. Обновление программы агента и управление Windows
взаимно блокируются. Во время известного запланированного перезапуска новую
установку запустить нельзя до отмены таймера или подтверждённого нового запуска ОС.
Журнал команд и общий журнал событий сохраняют назначение и изменение результата.

Проверка доступных обновлений ждёт до 15 минут, установка — до 2 часов. Работа
идёт в отдельном потоке, метрики продолжают поступать. После установки обновляется
инвентаризация. Частичные ошибки отмечаются с числом установленных/неуспешных пакетов.

Если агент/ОС прервались или операция превысила таймаут, результат может быть
неизвестен. Установка в Windows иногда продолжается после остановки вызывающего
PowerShell. Панель блокирует следующие команды до локальной проверки. Только
убедившись в состоянии Windows Update/перезапуска, используйте кнопку
«Подтверждаю локальную проверку неизвестного результата» с вводом ID сервера.
Она разрешает новые команды, а не останавливает текущую операцию Windows.

Успех команды перезапуска означает, что Windows приняла таймер, а не что сервер
уже перезагрузился. Фактический перезапуск проверьте по времени работы и новому
отчёту агента. При ошибке проверяйте Windows Update и системные журналы на сервере.
Пароли, токены и произвольные команды из панели не принимаются и не выводятся.
