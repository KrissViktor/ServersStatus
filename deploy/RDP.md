# Управление RDP и Shadow RDP

На странице Windows-сервера откройте «Пользователи RDP». После снятия защиты
(«Администрирование» → «Управление агентами» → замок) рядом с сеансами доступны:

- **Отключить**: отсоединяет пользователя, оставляет работающие приложения.
- **Завершить сеанс**: закрывает приложения и выполняет выход пользователя.
  Несохранённые данные могут быть потеряны. Требуются подтверждение сервера/
  пользователя и ввод его имени. Учётная запись Windows сохраняется.
- **Shadow RDP**: скачивает .cmd для подключения к активному сеансу через
  стандартный mstsc на вашем Windows-компьютере.

## Отключение и завершение

На Windows-агенте должна быть включена существующая настройка
`allow_remote_console: true`, службе нужны права управления RDP-сеансами
(обычно LocalSystem). Используется существующая защищённая очередь консоли;
переустановка/обновление EXE для этой возможности не требуется.

Действия требуют свежего отчёта (не старше 60 секунд), имени пользователя,
домена, ID сеанса и времени входа. Пока одна операция не завершилась, другая
не назначается, включая обновление агента и команды управления Windows.
Агент повторно проверяет пользователя, домен, время входа, протокол RDP и
состояние непосредственно перед вызовом WTSDisconnectSession/WTSLogoffSession.
Если сеанс исчез или изменился, команда завершается ошибкой.

После назначения окно показывает состояние операции. Успешный результат
означает, что Windows приняла действие. Фактическое состояние смотрите в
следующем отчёте агента (обычно через 10 секунд). Никакие пользователи не
отключаются во время просмотра списка или открытия подтверждения.

Результат доступен также в истории консоли с понятным названием операции.
В базе сохраняется исходная команда. При неизвестном результате сначала
проверьте сервер; в мини-консоли используйте подтверждение локальной проверки
результата перед повторной операцией. Существующая защита от повторного
выполнения после перезапуска агента применяется и к RDP-командам.

## Shadow RDP

Скачайте свежий файл для нужного пользователя и запустите его на своём
Windows-компьютере; при необходимости — от имени администратора.
Команда имеет вид:

```text
mstsc.exe /v:"SERVER" /shadow:12 /control /prompt
```

Нужны:

1. Сетевой доступ с вашего Windows-компьютера к целевому серверу и разрешение
   его имени. Если вы вне локальной сети, нужен доступ в неё, например VPN.
2. Учётная запись с административными/делегированными правами на сервере.
   Пароль подключённого пользователя знать не требуется. mstsc запрашивает
   ваши административные учётные данные средствами Windows.
3. Разрешение Shadow в политике Windows «Установить правила удалённого
   управления сеансами пользователей служб удалённых рабочих столов»
   (Computer Configuration → Administrative Templates → Windows Components →
   Remote Desktop Services → Remote Desktop Session Host → Connections).
   Выберите полный контроль с согласия пользователя, если это подходит вашей
   организации. Доступность функции зависит от редакции и политик Windows.
4. Разрешённое подключение в брандмауэре Windows согласно правилам вашей сети.

Панель не меняет политики/брандмауэр и не отключает согласие пользователя:
параметр /noConsentPrompt не используется. Пароли не вводятся и не сохраняются
на портале. Запускайте файл вскоре после скачивания: ID сеанса может быть
позднее использован Windows для другого входа. Перед подключением проверьте
имя пользователя в панели; взаимодействие и запрос согласия выполняет Windows.
