# Журнал разработки

## 6 ноября 2026 — первая версия

Языки: **Python** — веб-сервер, агент, Windows-служба и тесты;
**HTML/CSS** — начальная веб-панель; **SQL** — структура SQLite и запросы;
**JSON** — конфигурация агента. Команды установки приведены для Bash и PowerShell.

Созданы:
- Сервер FastAPI с входом, scrypt-хешами паролей, защищёнными cookie,
  ограничением попыток входа и индивидуальными ключами агентов.
- Приём и хранение отчётов за 30 дней, список последних показателей после входа.
- Агент psutil: CPU, RAM, диски, uptime, Windows-службы и файлы бэкапов.
- Обёртка агента для Windows Service, автоматический запуск и повтор отправки.
- Шаблоны systemd и Caddy для Raspberry Pi и HTTPS.
- README с установкой, настройкой и известными ограничениями.
- Интеграционные тесты входа, ключей, отчётов, ограничений и состояний бэкапов.

Панель первой версии показывает структурированные данные без графиков.
Реальные Windows-службы, ARM64 Raspberry Pi, внешний HTTPS и перезагрузки ещё
требуют проверки на вашем оборудовании. SQL msdb, проверка восстановления,
уведомления, настройки через панель и управление серверами пока не реализованы.

Проверено в облачной Linux-среде на Python 3.12: 3 теста прошли; отдельный
процесс Uvicorn успешно ответил на /health и показал форму входа по HTTP.

## 6 ноября 2026 — Windows-установщик без отдельного Python

На Python/tkinter создан графический установщик: URL, имя агента и скрытое поле
ключа; проверка HTTPS и авторизации до установки. Служба устанавливается в Program
Files, настройки — в ProgramData с правами SYSTEM/Administrators. Добавлен журнал
с ротацией и поддержка запуска службы из frozen EXE через pywin32 dispatcher.
GitHub Actions (YAML) собирает сервис и установщик PyInstaller на Windows x64,
проверяет запуск службы и сохраняет установщик с SHA256 в артефактах.
Локально проверена компиляция Python и отсутствие ошибок форматирования diff.
Сборка и работа на реальных Windows требуют отдельной проверки; Linux не собирает
Windows EXE. Тестовый запрос установщика отправляет нулевые метрики до запуска агента.

## 6 ноября 2026 — управление агентами из браузера

Python: добавлены авторизованные маршруты создания, перевыпуска ключа и удаления
агента. Формы защищены токеном, привязанным к текущей сессии. Идентификаторы новых
агентов проверяются, повторное имя отклоняется. Ключ хранится только как SHA256,

Перевыпуск сохраняет историю и сразу отзывает старый ключ; удаление требует ввода
имени и очищает историю. Приём отчётов повторно проверяет ключ внутри транзакции,
чтобы не принять отчёт одновременно с отзывом доступа.
HTML/CSS: отдельная адаптивная страница управления, ссылка в шапке панели,
поля регистрации, подтверждения действий и блок сохранения нового ключа.
Добавлен интеграционный тест полного цикла, проверки авторизации и защиты форм.

Результат проверки: все 5 интеграционных тестов unittest прошли в Linux-среде.

веб-службы; изменения схемы существующей базы не требуются.

## 6 ноября 2026 — красные уведомления и минимальный размер бэкапа

Python: агент и готовые правила используют 30 часов для ежедневной копии и
минимум 1024³ байт для всех копий. Добавлен статус too_small; просроченная копия
не маскируется начальным ожиданием стабильности. Сервер независимо оценивает
возраст/размер из отчётов, совместим со старым агентом и учитывает время после
последнего контакта. Несколько причин выводятся одновременно.

причинами; сообщения повторены у соответствующего правила. Нет связи — явная
пометка об использовании последнего отчёта. Минимальный размер не является
проверкой восстановления или целостности SQL.
Проверки: 13 unittest прошли, включая границы ровно 30 ч и 1 Гб, файл на один
байт меньше, превышение на секунду, одновременные причины и потерю связи.

## 6 ноября 2026 — Telegram-уведомления

Python/SQLite: отдельный worker server.notifications оценивает связь и бэкапы,
отправляет начало инцидента и восстановление. Дедупликация сохраняется в SQLite
между запусками. Изменение возраста не вызывает повтор. Ошибки отправки повторяются
с учётом retry_after; потеря связи и нестабильный файл не дают ложного восстановления.
Удалённые агенты/правила очищаются без сообщения о восстановлении. HTTPS/TLS включён,
исключения Telegram не раскрывают URL с токеном. Добавлены --test и --discover-chat.
Systemd/Bash: отдельные oneshot service и timer раз в минуту, защита от параллельных
запусков через flock, helper читает токен из root-only файла /etc вне репозитория.
Markdown: инструкция создания бота, ввода токена, определения чата, теста и запуска.
Проверки: тесты инцидентов, восстановления, дедупликации, повторной отправки,
retry_after и удаления агентов проходят с имитацией доставки. Реальную доставку
не выполняли: токен и чат пользователь задаст на Raspberry Pi.

Итог проверки: весь набор из 27 тестов прошёл; дополнительный тест транспорта
прошёл отдельно (plain text, таймаут HTTPS, retry_after и отсутствие токена в
тексте ошибки). Bash helper проверен bash -n, Python компилируется.
